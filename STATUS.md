## Known Issues

- The direct-download 0.1.0 preview intentionally has no production appcast. Its **Check for Updates…** command therefore reports a visible feed error until a later, independently approved feed deployment; the existence of the GitHub Release does not imply updater readiness.
- The non-Developer-ID update path has not passed the mandatory old-version → new-version matrix. Sparkle helper loading under the actual public ad-hoc build, tamper rejection, atomic replacement/relaunch, quarantine behavior and Screen Recording/Accessibility authorization continuity are unverified and release-blocking.
- The restricted embedded-notes appcast contract has local script evidence for exact structure, signature verification, no link/external destination, strict version/build monotonicity and fail-closed rejection. It still needs protected-workflow and clean-client runtime evidence for signed-feed status before presentation and no detached-notes request.
- Sparkle 2.9.5 does not publicly expose the extracted app before installation or enforce both enclosed bundle versions against the appcast. The protected release pipeline rejects a mismatched final ZIP, but production self-update remains blocked until the equivalent client-side contract is enforced by an upstream upgrade, reviewed hardening or replacement mechanism.
- Capture, quick editing, Canvas editing, history, output transactions and external file promises now share one authoritative update-admission boundary. The external-drag lease spans drag admission through asynchronous promise completion and fails closed for a nonconforming destination; third-party Finder/app drag destinations still need the manual matrix.
- The manual matrix in `docs/MANUAL_TESTING.md` has not been completed on physical 1x/2x multi-display arrangements, Mission Control/Spaces/Stage Manager, permission revoke/restore, display hot-plug, Chinese IME, VoiceOver or third-party drag destinations.
- The disposable XCUITest Runner remains intermittent outside the currently passing region flow; it still needs a stable Input Monitoring identity, and Xcode 26.6 must avoid its accessibility-value deadlock, before every end-to-end pointer test can run reliably. The current inline-text UI retry typed mixed text successfully but then failed while Xcode resolved the system `CursorUIViewService` AX subtree; it is not reported as a pass. Debug/Release compilation, the complete 108-test SwiftPM run, the passing targeted copy/Pin/palette XCUITests, deterministic native TextKit/palette-ownership regressions, signing, install and runtime startup are independently green.
- Window-level smart snapping is automatically covered and needs no Accessibility grant. Inner-control snapping still needs one manual pass after granting Ushot Accessibility access, because automated test runners must not silently request or mutate the user's system privacy authorization.
- macOS 26.5 emits one launch-time AppKit `layoutSubtreeIfNeeded` recursion warning while FrontBoard updates the menu-bar status-item scene. An LLDB breakpoint at `_NSDetectedLayoutRecursion` captured a stack consisting entirely of AppKit/FrontBoard scene and window-frame code, with no Ushot frame; removing Ushot's detached toolbar measurement did not change it, so that experiment was reverted. The warning is observable but currently outside the app's call stack and has not affected launch or capture behavior.
- Computer Use can inspect and activate the frontmost toolbar child window but cannot target the covered sibling image panel by coordinates, so it cannot provide an independent high-speed visual recording of this multi-panel flow. The native regression instead forces actual window display after every input update and validates the frame before continuing; the final subjective rapid-typing check remains a short manual acceptance step in the newly installed Release app.
- The historical ad-hoc → Apple Development local migration required an interactive Screen Recording authorization. The permanent bundle identifier migration and future ad-hoc public updates may require authorization again; continuity must be measured and documented rather than assumed.
- Accessibility and launch-at-login flows still need interactive permission testing. The code fails visibly and logs errors rather than swallowing permission failures.
- Developer ID distribution signing and notarization are intentionally deferred because no paid Apple Developer Program membership or distribution credentials are available. Stable Apple Development signing is verified for local installation only and is not the public trust mechanism.
- Product identity and Apache-2.0 licensing are resolved. Final app icon/brand asset licensing and the EdDSA recovery drill remain open in `docs/DECISIONS_NEEDED.md`.
