# AGENTS.md

## Engineering rules

- Do not run a full type-check or full build after every small edit. Use broader validation only for broad changes; otherwise call out what still needs attention.
- Fail fast. Do not swallow errors or hide failures behind fallback behavior.
- Fix root causes instead of layering symptom-specific patches.
- Keep critical paths observable with privacy-safe logs and explicit lifecycle reasons.
- Preserve traceability at every important workflow boundary.
- Update this file and the product documentation when the technical stack or product direction changes.
- Ask before creating a branch for a large refactor or experimental change.
- After every completed change that affects app code or resources, build the stable locally signed Release app, replace `/Applications/Ushot.app`, relaunch it, and verify that the installed binary matches the new artifact before handing the task back. Do not leave the user running an older installed app after reporting completion. This local development install is distinct from the intentional ad-hoc public artifact.

## Product identity and licensing contract

- The public product and application bundle name is `Ushot`, the bundle identifier is `io.github.ischeneycc.ushot`, and the canonical repository is `https://github.com/isCheneycc/ushot`. Internal target/module names may remain `UshotApp`/`UshotCore` where changing them would be an unrelated migration.
- Debug hosts use the distinct bundle identifier `io.github.ischeneycc.ushot.debug` and isolated preferences/Application Support storage. Debug and UI-test builds must never register or request TCC services under the production identifier; no disposable Ushot host app may remain registered with LaunchServices, and after validation the release builder must remove any exact host path that is registered and verify its absence. A stable local Release keeps the production identifier; after an atomic local install, the exact `/Applications/Ushot.app` must be registered and verified with LaunchServices before launch. Recoverable bundles must use a non-`.app` suffix and remain absent from LaunchServices. Rollback must unregister and verify a failed replacement before moving it away, then re-register any restored app.
- Source published in this repository is licensed under Apache-2.0. A future paid edition may contain separately distributed closed-source modules or services, but no later commercial decision may revoke or narrow the Apache-2.0 rights already granted for published code.
- Screenshot pixels, annotation content, clipboard content, exports and history remain local. Ushot has no account, telemetry, analytics, advertising identifier or system-profile submission.

## Region capture product contract

- Region mode freezes every participating display before any selection overlay is presented. That frozen desktop is the visual and pixel source of truth until the user cancels or commits an output.
- While the initial region selection remains unlocked, its magnifier must follow the pointer synchronously and sample only that frozen desktop. The lens uses rounded pixel-content clipping, a subtle shadow and dual-contrast hairline keylines—never an opaque padded black frame. A one-physical-pixel grid plus a dual-contrast crosshair identifies the actual sampled pixel even when the crop shifts at a display edge. A compact attached HUD reports the display-local backing-pixel X/Y and the current selection's physical-pixel size, and labels a smart-snap candidate as Window or Control. The magnifier stays visible for hover, creation and edge resizing, hides during whole-selection movement, and disappears once confirmation locks the selection.
- Region capture is a selection-confirmation workflow, not a screenshot-preview workflow. Mouse-up retains the frozen desktop, selected pixels and outside mask, then shows exactly one blue selection border with eight working resize handles, a transparent annotation surface and the complete annotation/output toolbar with Pin and Cancel added. Every point on each blue border edge is a resize target with the matching directional cursor; users do not need to hit a visible handle. Pinned-image-only controls—Click Through, Temporarily Hide Image and Open Canvas Editor—must be absent until the region has actually transitioned through Pin. Confirmation must not expose a cropped screenshot or pinned-image window.
- Region selection chrome and final region output share one Capture-settings corner radius (`Settings → Capture → Region Corner Radius`, default **12 px**, independent `px`/`pt` unit, clamped to half the shorter selection side). The pre-confirmation overlay hole, confirmation blue border, annotation-surface clip and Copy/Save/Pin composite all use that radius so the frame is WYSIWYG; selection geometry remains an axis-aligned desktop rectangle. Zero disables rounding. Window and display capture stay square unless a document explicitly sets canvas effects.
- In-app language is user-selected under **Settings → Advanced → Language** (English / 简体中文). The factory default is **Simplified Chinese**; string catalogs still use English as the source language. Changing language restarts Ushot so AppKit menus and windows re-read localizations.
- Every confirmation-handle center must sit exactly on the blue selection border. Between visible handles, the resize band may reach at most 2 pt into the selected canvas; at each visible 8 pt handle, only that handle's 4 pt interior half may claim input. Any remaining enlarged hit-target margin belongs to transparent chrome outside the selected desktop frame and must never inset the visible handles or change the selected/output geometry.
- The transparent confirmation canvas must exactly match the selected desktop frame and must receive every interior pointer event; only the eight resize hit regions may route to the surrounding chrome. Once confirmation begins, every full-screen frozen-overlay window is visual-only and must ignore pointer events, leaving the annotation panel as the single input owner. Mixed flipped/non-flipped AppKit layout must never distort that frame or leave either overlay or chrome intercepting annotation input.
- Mouse-up must never materialize or pin an output implicitly. An internal frozen-pixel crop may be cached for effects and final composition, but it is not a completed screenshot and must not replace the frozen-overlay presentation. After region confirmation, double-clicking empty interior space copies the latest composite and closes the overlay when **Settings → Capture → Double-click region to copy** is on (factory default on). Recognition is the second pointer-up of an empty Select-tool click, by AppKit `clickCount` or by timestamp/position pairing; a single mouse-up still does nothing. Physical mouse, trackpad press-twice and tap-to-click must all work. Confirmation body-move waits until the press travels about 8 pt so micro-jitter cannot steal the second click, and the pinch-zoom recognizer must not delay primary mouse-button events while the region is still a confirmation draft. Resize handles, existing annotations, active text input, drawing tools and an in-progress body-move must not take that path; turning the setting off restores the previous double-click-does-nothing behavior.
- The confirmation toolbar keeps every annotation and capture-output tool functional while omitting controls that operate only on an existing pinned window. Successful Copy or Save resolves the latest composite, closes the complete overlay/annotation-surface/toolbar group and ends capture; cancelling a Save panel leaves confirmation active. Cancel and Copy/Save must leave any existing pinned image untouched.
- A newly committed region-confirmation annotation must publish with an empty selection, so Rectangle, Ellipse, Line, Arrow, Freehand, Highlight, Spotlight, Text, Counter and source-anchored effects never show editable selection chrome immediately after creation. With a gesture-creation tool still active, a later short click on a stored annotation selects it and a short click on empty canvas clears the current selection without switching tools, while a drag still creates a new annotation; Select-tool hits remain the universal explicit selection path. This region-only creation policy must not change the full Canvas Editor's existing add-and-select behavior.
- Annotation resize handles own their interaction and directional cursor from mouse-down through mouse-up. Resizing must update on the first nonzero pointer movement; the body-move click threshold must never delay a resize or substitute the closed-hand cursor.
- Pin resolves the latest composite, closes the capture overlay, and advances the confirmation surface into the pinned-image lifecycle. Pin admission rejects any active pointer press so a move or resize must commit before composition begins. Only after composition succeeds may the new pinned surface join the identity-keyed pinned-image collection; it must never close or replace an existing pinned image.
- Explicit Pin is not governed by the automatic-pinned-presentation preference.
- Confirmation presentation and frame updates must not animate. With Select active, dragging empty canvas space moves the complete selected desktop frame; existing annotations keep their canvas-local geometry and move with it. During a live resize, the transparent annotation canvas is instead a 1:1 viewport into the original global-desktop document: changing an edge may reveal or clip content, but must never translate or non-uniformly scale existing annotations, selection handles or stroke widths in intermediate frames. The canvas and chrome geometry must update synchronously before drawing. Mouse-up then recrops the original frozen desktop image off the main actor and rebases the document plus its undo/redo timeline to the committed selection without creating a second visual-only handle layer.
- The initial confirmed selection, every live resize frame and the mouse-up commit must use the same canonical whole-point desktop frame. Never preview fractional AppKit pointer geometry and only integralize at commit: changing the backing-pixel phase during a drag makes otherwise stationary annotations shimmer or snap on release.
- Capture admission is atomic. If any capture session—including an uncommitted region confirmation—is active, a repeated global capture shortcut must be rejected non-modally without resetting, cancelling or otherwise mutating the active session. It may provide a beep and privacy-safe log, but must never run a hidden modal alert behind capture-level panels or steal input from the existing toolbar and overlay.
- A region created through Pin preserves the selected desktop frame, remains movable and proportionally resizable, starts without the quick-annotation toolbar, and is read-only by default; ordinary pointer input must never keep editing annotations after Pin.
- A successful toolbar Copy or screenshot-level `Command-C` on a newly presented window/display capture writes the latest composite and then closes only that image and toolbar. Native text-field copying remains native, output failure leaves the screenshot available for retry, and automatic copying never triggers this dismissal. A region advanced through explicit Pin remains persistent after toolbar/keyboard copy, as does Copy Screenshot from any pinned-image context menu. Copy and Save run as generation-qualified output transactions: they may start only from committed region geometry with one mutation owner, freeze canvas/resize/toolbar mutation until completion, and validate the same desktop frame before writing. Escape, Cancel, explicit close and application termination invalidate the matching transaction so a stale renderer can never write output, release a newer transaction or fire a late lifecycle callback. Output failure must finish and unlock the matching transaction before presenting exactly one visible error above every capture-level surface; never run a hidden modal alert while screenshot input is frozen.
- Window, current-display, selected-display and all-display capture previews commit their final pixels before ordering front, then use one short alpha-only ease-out transition shared by the image and visible toolbar. Every preview is retained under a stable identity until that specific surface closes; a new preview must not replace an older one, and otherwise identical pointer-relative origins are offset so stacked images remain discoverable. Reduce Motion uses a shorter, higher-opacity transition. Region confirmation remains strictly animation-free, and any close or opacity interaction must terminate only that surface's entrance owner explicitly.
- Screenshot capture and presentation preserve one native pixel contract. Window capture validates native body scale, complete framing and display identity before committing pixels; a preview derives its aspect ratio from immutable native geometry, uses nearest-neighbor sampling only when both destination axes are physically one-to-one, and uses high-quality interpolation for every upsample, downsample or non-uniform destination. Native-size restore and cumulative trackpad magnification derive both axes from the same immutable aspect ratio so backing-pixel quantization cannot accumulate drift.
- A read-only pinned image uses an open-hand cursor over its movable body, switches to an uninterrupted closed hand immediately on mouse-down—even before any movement crosses the drag threshold—and shows the matching horizontal, vertical or diagonal frame-resize cursor over every resizable edge and corner. Cursor rectangles are the single hover owner; one app-controlled body-move interaction owns mouse-down, global-pointer-delta movement and mouse-up as a single lifecycle. During that complete press, the proposed panel origin equals the begin origin plus the global pointer delta across display seams; delayed per-screen AppKit constraints must not create an edge dead zone. Non-drag placement, restore and resize paths retain their normal visibility constraints. Do not delegate pinned-body movement to Window Server dragging, which can replace the closed hand while the pointer is held below its movement threshold. The active press must not compete with cursor-stack pushes or mouse-move setters.
- A pinned image's context menu exposes Copy Screenshot and Show/Hide Toolbar. Showing the toolbar enables annotation editing and restores Click Through, Temporarily Hide Image and Open Canvas Editor; hiding it ends any active edit and restores read-only input.
- Mouse-up must return promptly: crop the frozen selection off the main actor, cache the frozen overlay image, and prepare/reuse the complete region toolbar instead of constructing it synchronously after selection.
- Smart region snapping is enabled by default. Hovering identifies the topmost frozen ScreenCaptureKit window immediately; clicking accepts it, while dragging still creates a manual rectangle. Only front-to-back, layer-zero windows owned by another application are valid candidates: menu-bar, Dock, desktop and WindowServer surfaces must be rejected both during discovery and hit testing so they can never hide cross-application windows. With optional Accessibility permission, the same hover path resolves the useful control-to-window ancestor hierarchy inside the owning app. High-frequency pointer events must be coalesced through one serial resolver and must never synchronously demote an already verified control to its window while a newer lookup is pending; the complete verified hierarchy remains stable across transient web-accessibility paths while its frames still contain the pointer. Tab moves one valid level toward the parent/window, Shift-Tab moves one level toward the child, and Option-scroll remains available. A user-selected ancestor persists only while the deepest hovered control is unchanged; when that leaf changes, both the HUD level and visible snap frame reset atomically to the new deepest control. Window snapping must keep working when Accessibility is absent, denied or revoked, and Ushot's overlay must never be queried as the target element.
- Keep the selection overlay, transparent annotation surface, confirmation toolbar and pinned panel as distinct lifecycle owners, and log frozen-desktop readiness, region geometry, preparation timing, toolbar placement, Copy/Save/Pin intent, editing-state transition and close reason.

## Annotation editor state contract

- The color-picker card keeps the sampled pixel and copy result in one live generation, prioritizes the actual copy value and swatch, then groups RGBA channels, display/color-space/coordinate metadata and keyboard shortcuts in that reading order. It omits source-profile metadata, keeps shortcuts in two whitespace-grouped rows, remains compact, localizes every visible label, and exposes the same ordered sample details to assistive technologies without duplicating the copy representation.

- Crop is not a user-facing annotation tool: it must be absent from the region/pinned quick toolbar, the full Canvas Editor rail and shortcut settings, and no keyboard shortcut may activate it. Preserve decoding and authoritative rendering of legacy crop state so existing documents remain readable and exportable.
- Publish each annotation document and its valid selection as one atomic observable state. A render must never expose selected IDs that are absent from the document emitted in that same transaction.
- Annotation document schema 2 owns the versioned text-layout payload. Schema-1 documents migrate in memory without changing legacy tight text geometry and are re-encoded only as schema 2; a schema-1 document that already contains schema-2 layout state and every unknown/future schema must fail closed. Never write new layout semantics under an old schema that a previous release would accept and destructively rewrite.
- SwiftUI inspectors must edit a stable value draft keyed by the selected item's identity. Never create a long-lived `Binding` whose getter force-resolves an item ID from a mutable annotations array; undo, delete, replacement and view teardown must not crash while the inspector graph is being dismantled. Every continuous inspector gesture or focused text edit owns a generation-qualified document transaction: previews publish without growing undo history, commit appends exactly one complete undo record, cancel restores the complete starting state, and stale owners cannot commit or cancel a newer edit. Undo and redo timelines are observable state in their own right, so finishing a continuous edit must refresh command availability even when no additional document publication follows the commit.
- A full Canvas Editor window is the exclusive mutation owner for its `AnnotationEditingSession`. Before it is shown, the matching identity-keyed pinned surface must commit or reject active inputs, end inline text, hide its quick toolbar and become a read-only mirror without clearing the shared selection or preview exclusions; every other pinned surface remains independent. That mirror must draw no annotation handles or text chrome. Editor close releases a generation-qualified lease only after window teardown, ignores stale releases after an immediate reopen or pinned close, and restores only the matching surface's toolbar visibility that preceded the handoff.
- Mosaic and Blur are fixed source-anchored effects. They may be selected, but they expose no resize handles or scale controls and must never be moved or resized after creation by pointer drag, arrow-key nudge, alignment, distribution or inspector editing.
- Freehand is a path-only brush annotation. It may be selected and moved, but it exposes no frame-resize handles or scale controls; its captured pointer path and stroke width must not be rescaled by a generic bounding-box transform.
- Filled, double and tapered arrowheads use a concave paper-plane rear join that converges diagonally into the shaft; they must never fall back to a flat triangle base or expose a gap/round-cap bulge at the join. Live preview, committed canvas, hit testing, style thumbnails and export share the same presentation-space geometry. Any future visual renderer-semantic change must advance the cached-preview render revision independently of the editable document schema, invalidate only affected legacy previews, and stamp the new revision only after a successful authoritative render.
- Highlight stores an opaque semantic color in `strokeColor` for editor and toolbar synchronization, while its matching `fillColor` owns the fixed translucent presentation alpha. New highlights use the factory yellow semantic color while it remains configured, otherwise they use the configured general default; legacy-default highlights still normalize to their historical yellow. Never use a transparent stroke as a renderer sentinel. Recoloring must preserve the fill alpha, and legacy sentinel styles must be normalized observably before editor admission.
- Removing any configured palette color never mutates existing annotations. When one is selected later, the toolbar presents that historical color as a disabled temporary current-value entry without restoring it to the configured palette or letting it recolor other annotations; choosing a configured color removes the temporary entry. Only a selected existing annotation may expose an off-palette current color—tool defaults and new drafts must be reconciled to configured colors.
- The annotation toolbar color control is a native secondary menu, never an `NSColorPanel`. Its ordered, nonempty, versioned palette is the single source of truth. A fresh install starts with red/orange/yellow/green/blue/purple, but every color—including those six factory defaults—may be removed, re-added or replaced only under Settings → Editor, and the factory six can be restored explicitly. Selecting a color must let native menu tracking end before document/TextKit mutation begins, must reuse the palette's cached swatch, and must log menu-action, queue and application timing without logging screenshot or text content.
- The annotation toolbar's numeric line-width field owns its raw editing string independently from the committed numeric style. It must preserve valid intermediate input such as `1.` so users can type `1.5` in order; never attach a formatter that rewrites the field during editing. Apply only lexically valid finite values, enforce the supported precision/range explicitly, and format once on commit or rejection.
- A line-width edit captures one stable semantic target when field editing begins. If one or more editable stroked annotations are selected, the field remains enabled even under Select, every valid keystroke previews those exact items immediately and commit creates one undoable document transaction without changing the persisted tool default. With no editable selection, the edit changes the current tool's independently owned creation default, leaves existing annotations and the document undo stack untouched, persists only on commit, and the very next annotation uses it without requiring a tool switch. Selection presentation style and creation-default style must never share mutable ownership; every atomic Add/Paste/Undo/Redo/selection update must resynchronize the displayed target, while clearing a selection restores the current tool default. Hiding the toolbar, Pinning or recycling it must cancel and detach both the field and canvas sides of any active transaction before changing lifecycle owner. A unit change first commits or rejects and detaches the current raw input, then converts and persists the default unit atomically.
- Text, Rectangle and Circle each have an independent default color in Settings. Changing color while a text editor or annotation selection is active edits that object; beginning a new Text annotation resets to the configured Text default. Text also has a configurable default installed font, with the macOS system font represented explicitly by a nil font name.
- Text annotations have one dedicated chrome in both active input and ordinary selected states: one accent border, font-size resize handles at the top-left, bottom-left and bottom-right corners, and a top-right close button that discards a new draft or deletes existing text through one undoable transaction. Text must never fall back to the standard eight-handle frame transform. Inline input keeps the native editor active while resizing and has a clear background; neither the AppKit text view nor its framing layer may fill the selected pixels underneath. Clicking inside an active field must move the caret without ending editing; Return commits, and Shift+Return inserts a hard line break. Additional lines keep the first-line baseline and grow the field and committed rectangle downward. New overlong input grows the interaction field monotonically up to its cap, then wraps so the leading characters stay visible. A persisted wrap width wider than the 520 pt interaction viewport remains the TextKit document width and is exposed through clipping plus alignment-aware horizontal caret scrolling; opening it must never silently rewrap at the viewport width. The editor, committed renderer, selection geometry and font-size limits consume one TextKit layout plan with identical character ranges, line metrics and real installed-font ascent/descent/leading; fixed `fontSize` height approximations and separate Core Text break decisions are forbidden. The accent chrome keeps the same inset on all four sides around the glyphs while typing, after commit, and when re-editing; a later click must not add a second ring of padding. Text layout generation, chrome mode and canonical untransformed wrap width are persisted as explicit item state. A missing layout payload has exactly one deterministic meaning—published legacy tight chrome—and must never be inferred from floating-point rectangle geometry; a no-op re-edit of such an item must preserve the complete original item and keep that payload absent. Text/content/font edits from the Canvas inspector must reflow geometry and persisted layout in one undoable document mutation. The document baseline anchor is the rendering source of truth, so fallback-font metric changes must be corrected in place and focus-change commit must not move the glyph line. Legacy text with rotation or non-uniform scale must remain selected and fail inline-edit admission observably until the native editor can reproduce its complete presentation transform; never flatten or discard that transform to make editing appear to work.
- The live `NSTextView` must run the canonical TextKit stack only in untransformed document coordinates. Canvas zoom and a supported uniform item scale are applied once by the document host's bounds-to-frame projection; presentation-size font, wrap and line-height recomputation are forbidden because fractional scales can change line ownership and accumulate baseline drift. Every live visual line must retain the persisted UTF-16 range and project its two-dimensional visual origin and canonical baseline from the same revision-qualified renderer-ready plan used by output. The current payload stores its exact layout input, ranges, origins, baselines, metrics, glyph bounds, content height and lowercase SHA-256 shape fingerprints. Each fingerprint binds the complete source bytes of every primary and fallback font used by the line, including every color-glyph strike and variation state: URL-backed cache identity must include the file's stable identity and generation metadata, while a font without a readable URL may reuse a complete-table digest only for the same immutable `CTFont` object. A transient geometry plan carries an explicit non-persistable marker; every payload, encode, migration, inspector, inline commit and controller publication boundary must obtain a renderer-ready plan through a throwing API first. Decode validates immutable structure, input binding and rectangle geometry without resolving fonts; rendering and edit admission separately reproduce full-paragraph bidi/fallback shaping for that payload revision and surface a missing font, unreadable source or changed shape without crashing, silently substituting, misclassifying history as corrupt or hiding the record. A dedicated layout-manager delegate must apply the persisted baselines to ordinary and extra line fragments. Version-1/version-2 draft migration validates only after rebuilding current explicit geometry, while a missing published legacy payload remains outside the new invariant.
- Spotlight is available in the quick toolbar and full editor. While the user is dragging out a new Spotlight region, keep the source canvas unchanged and show only the normal accent selection outline; apply the dark translucent outside mask after mouse-up. Once committed, one rectangular clear focus region keeps the source pixels unchanged while the rest of the canvas is dimmed, and interactive/exported committed rendering must share that implementation. During region-canvas resizing, the committed mask must use the current live viewport bounds on every frame so newly revealed areas dim immediately rather than waiting for mouse-up recropping.

## Editor settings product contract

- Settings → Editor uses progressive disclosure: the page shows toolbar colors, one three-tool Text/Rectangle/Circle master-detail editor and one compact live preview. Only the selected tool's relevant controls are visible; do not restore separate always-expanded color/font/drawing sections.
- Every color control that displays a current value must pair the swatch, localized semantic name and exact `#RRGGBB` value. Unselected toolbar swatches stay compact, while the selected color receives a clearly visible ring and combined value summary.
- The default page owns only quick selection and tool defaults. Managing the complete toolbar palette belongs in the separate Manage Palette sheet. Any configured color may be added or removed, the last remaining color cannot be removed, and deletion must ask for a valid surviving replacement and atomically redirect every default that used it; existing annotations never change. Palette-only restore offers two explicit outcomes without resetting non-color editor defaults: replace the palette with exactly the factory six and redirect removed defaults to red, or restore the factory six while preserving every custom color and its tool-default ownership.
- Every Text/Rectangle/Circle item in the tool-default master list is one full-row button; its complete visible row, including transparent trailing space, must switch the selected tool.
- Text font selection is searchable and previews the actual family. Text, Rectangle and Circle summaries update immediately. Font size, line width and rectangle radius each default to physical pixels and independently support `px`/`pt`; changing a unit atomically converts its stored value at the Settings window's current display scale so the compact preview does not jump, then persists the value and unit together. New annotations apply the selected unit against the target capture's backing scale. Rectangle radius defaults to 4 px.
- Restore Editor Defaults affects only `EditorSettings`; it must not reset capture, output, shortcut, history or other application preferences.

## Shortcut settings product contract

- A global shortcut may use F1–F20 without Command, Option, Control or Shift. Every ordinary key still requires at least one of those persisted modifiers so a global registration cannot silently capture normal typing; Fn/Globe only exposes a standard function-key event and is never stored as a shortcut modifier.
- Function-key identity and display names come from one canonical physical-key mapping shared by recording, settings presentation and persistence. Registration remains transactional: a macOS-reserved or conflicting function key must surface the existing registration error and leave the previous shortcut active.
