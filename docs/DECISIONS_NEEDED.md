# Product Decisions

> Historical rollout record. The first-production-feed gates below were resolved before Ushot 0.1.4 (build 5) became the first v1 item. Ushot 0.1.5 and 0.1.6 subsequently extended that authenticated history. Current release requirements live in `AGENTS.md` and `docs/RELEASING.md`.

## Confirmed

- Public product and application name: `Ushot`.
- Bundle identifier: `io.github.ischeneycc.ushot`.
- Canonical public repository: `https://github.com/isCheneycc/ushot`.
- Source license: Apache-2.0.
- Initial distribution: official GitHub Releases, Apple Silicon and macOS 14+.
- Initial trust model: intentional ad-hoc application signature, no Developer ID and no Apple notarization. First installation documents a quarantine-removal step limited to the official release.
- Release readiness is split: a direct-download GitHub Release may be published without extending the production appcast. The protected workflow defaults to direct-download mode and requires an explicit `publish_update_feed=true` decision to sign and deploy a feed extension.
- Update rollout: the 0.1.1 client remains on the legacy `https://ischeneycc.github.io/ushot/updates/appcast.xml`, which stays permanently absent. Ushot 0.1.2 (build 3) is the published first manual-install hardened transition and uses `https://ischeneycc.github.io/ushot/updates/v1/appcast.xml`; its immutable GitHub Release was published with that endpoint still absent. Because its parsed-item policy cannot detect authenticated XML metadata that parsing collapses, published Ushot 0.1.3 (build 4) is the second manual GitHub-only transition. Protected run [`31078896953`](https://github.com/isCheneycc/ushot/actions/runs/31078896953) used `publish_update_feed=false`, anonymously verified exactly five assets, skipped signing/feed/Pages jobs and left both appcast URLs at HTTP 404. The complete evidence gate passed before protected run [`31141110871`](https://github.com/isCheneycc/ushot/actions/runs/31141110871) published 0.1.4 (build 5) as the first v1 feed item. Protected runs [`31552493658`](https://github.com/isCheneycc/ushot/actions/runs/31552493658) and [`31864175412`](https://github.com/isCheneycc/ushot/actions/runs/31864175412) extended that authenticated history with 0.1.5 (build 6) and 0.1.6 (build 7).
- Update framework and source: the runtime must use a reviewed Ushot Sparkle fork with mandatory signed-feed validation, exact extracted short/build identity and independent archive EdDSA validation. The published 0.1.2 host uses immutable fork tag `2.9.5-ushot.2` at revision `f4d8362bf9b6231596db3a0cc8812fdca8100961` and requires `SURequireExactUpdateVersionIdentity=true`, `SURequireEdDSAUpdateArchiveSignature=true` and framework capability marker `SUUpdateVersionIdentityHardeningVersion=1`. Published `.3` is the historical authenticated-XML-hook predecessor. The published Ushot 0.1.3 transition pins fork tag [`2.9.5-ushot.4`](https://github.com/isCheneycc/Sparkle/releases/tag/2.9.5-ushot.4) at revision `3d81360ff115ffb80222c2723d72cb4cfa802774` (SwiftPM ZIP SHA-256 `d8d36e5b5ee9e97b17babc1beeb26795b96558cafe5450130aafa5b169d5c829`) and additionally requires `SURequireHostSignedAppcastValidation=true`, `SUMaximumSignedAppcastContentLength=1048576`, the exact authenticated-XML pre-parse hook and framework markers `SUHostSignedAppcastValidationVersion=1` plus `SUFeedDownloadSizeLimitVersion=1`. The appcast wire response is limited to the 1 MiB authenticated prefix plus a 512-byte signature trailer using both declared-length and incremental streamed enforcement; the separate persistent ZIP/archive download is not subject to this feed cap. The hook and release pipeline reject duplicate/misplaced metadata, wrong namespaces, DTDs and entities before parsed objects can hide them. Official upstream Sparkle 2.9.5 publishing tools continue to generate and sign the appcast. Restricted-Markdown release notes are embedded in each signed item, and immutable archives live on the official GitHub Release. Links/images/raw HTML/URL-like destinations inside notes, detached release-note URLs, item links, full-release-note URLs and deltas are forbidden; only the committed zero-item `updates/v1/appcast.xml` seed may bootstrap exact 0.1.4 (build 5). Every later version and build must each be strictly greater than every item retained in the authenticated production appcast.
- Update behavior: manual checks only; no automatic checks/downloads, telemetry, analytics or system-profile submission.
- Commercial direction: the open-source core remains Apache-2.0. Future paid capabilities may be separately distributed closed-source modules or services, without changing rights already granted for published code.

## Completed first-production-feed gates

- The 0.1.3 → 0.1.4 clean-account ad-hoc update matrix recorded exact-production-URL isolation, helper loading, exact short/build mismatch rejection, strict archive EdDSA, replacement and active-work admission.
- Pipeline and runtime authenticated-XML validation passed for signed-feed status, exact XML namespaces/hierarchy, duplicate metadata, wrong namespaces, DTDs/entities, unrestricted or detached notes, external destinations and extra release-notes requests.
- The malicious signed-fixture/two-version runtime matrix passed with the strict host booleans, positive integer `SUMaximumSignedAppcastContentLength=1048576`, all three integer framework markers and expected hook ownership. It proved missing/wrong key, marker or hook rejection; declared and chunked appcast overflow rejection while a larger persistent ZIP remained eligible; duplicate/wrong-namespace/DTD/entity rejection before parsing; post-extraction short/build mismatch rejection; and archive EdDSA failure without fallback to a matching application code signature. Source, local startup and CI publication checks remain complementary, not replacements for those adversarial client results.
- Developer ID distribution remains disabled pending its separate Developer-ID-specific runtime evidence. Joining the Apple Developer Program is not needed for the current ad-hoc rollout.
