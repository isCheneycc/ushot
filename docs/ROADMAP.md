# Roadmap

## Implemented foundation

- Phase 0 — repository, native project, centralized configuration, app shell, dependency container, logging and test target.
- Phase 1 — menu bar, versioned settings, permission guidance, login item and conflict-safe Carbon hot keys.
- Phase 2 — current/selected/all-display, window and region capture backed by ScreenCaptureKit and tested global geometry.
- Phase 3 — one persistent current-screenshot panel with replacement semantics, copy, save, drag, resizing and an attached annotation toolbar.
- Phase 4 — versioned non-destructive annotation model, renderer, commands, undo and quick annotation tools.
- Phase 5 — multi-window Canvas Editor sharing the Phase 4 document and renderer.
- Phase 6 — managed-color pixel picker and point/pixel screen ruler across displays.
- Phase 7 — opt-in editable history, accessibility/localization work, performance validation and local release packaging.

## Phase 8 — open-source release and manual updates

Status: direct-download publication and production-updater readiness are tracked independently.

- Adopt the permanent `Ushot` product name, `io.github.ischeneycc.ushot` bundle identifier, `isCheneycc/ushot` repository and Apache-2.0 license.
- Integrate Sparkle behind the existing `UpdateChecking` boundary with manual checks only and an embedded EdDSA public key. Keep the 0.1.1 legacy `/updates/appcast.xml` permanently absent; pin 0.1.2 and later to `/updates/v1/appcast.xml`. Generate that feed with the official upstream Sparkle 2.9.5 `--embed-release-notes` tool, require one signed restricted-Markdown description per item, reject all note links/external destinations plus detached notes, item links and deltas, enforce exact raw RSS/Sparkle structure and strictly increasing versions/builds, and deploy no Pages payload other than the signed v1 appcast.
- Produce versioned, validated and immutable ad-hoc arm64 DMG/ZIP/dSYM/manifest/checksum assets without Developer ID or notarization. Byte-for-byte reproducibility is not assumed. The protected workflow's default direct-download path publishes and anonymously verifies all five GitHub assets without reading an update key or creating a Pages payload.
- Preserve 0.1.1 as the published direct-download preview whose manual update command reaches the permanently absent legacy endpoint.
- Published 0.1.2 (build 3) as the first manually installed hardened transition with `publish_update_feed=false`. Its runtime fork requires `SURequireExactUpdateVersionIdentity=true`, `SURequireEdDSAUpdateArchiveSignature=true` and framework capability marker `SUUpdateVersionIdentityHardeningVersion=1`, then rejects extracted short/build mismatch and archive EdDSA failure without a code-signing fallback. The immutable five-asset Release passed anonymous public download verification while the v1 feed remained absent.
- Correct the authenticated raw-XML and unbounded-feed gaps before exposing that endpoint. Parsed `SUAppcastItem` values collapse metadata that the signed bytes may duplicate or place under a wrong namespace, so 0.1.3 (build 4) is an unpublished second manual transition. Fork tag `2.9.5-ushot.3` remains only the historical authenticated-XML-hook predecessor; the host must pin the now-published [bounded-feed successor Release](https://github.com/isCheneycc/Sparkle/releases/tag/2.9.5-ushot.4), exact tag `2.9.5-ushot.4`, revision `3d81360ff115ffb80222c2723d72cb4cfa802774` (SwiftPM ZIP SHA-256 `d8d36e5b5ee9e97b17babc1beeb26795b96558cafe5450130aafa5b169d5c829`). It adds `SURequireHostSignedAppcastValidation=true`, an exact authenticated-XML pre-parse hook and `SUHostSignedAppcastValidationVersion=1`, plus exact `SUMaximumSignedAppcastContentLength=1048576` and `SUFeedDownloadSizeLimitVersion=1`. Appcast transport admits at most the 1,048,576-byte authenticated prefix plus its fixed 512-byte signed-feed trailer (1,049,088 wire bytes total), rejecting oversized declared `Content-Length` before buffering and enforcing the same ceiling incrementally for chunked or otherwise undeclared responses. The cap applies only to temporary appcast downloads, never persistent update-archive/ZIP downloads. Publishing the fork is dependency evidence, not publication of Ushot 0.1.3.
- Protect the EdDSA private key. The owner approved the pre-0.1.3 rotation, declined iCloud and accepted the single-provider residual risk. The new key remains in its dedicated staging Keychain account; the old key and same-disk ciphertext remain retired evidence. The private recovery repository is committed once and archived at `9fe3d07a31bad91c6b75142955f31d1c30816ec1`, ciphertext SHA-256 `f308c694d6597a52a700ab4f9b97386ee17bd5332ad7725655fd13ab666155d0`; its fresh-clone checks passed and the protected signing Secret was replaced through stdin. Temporary local production-key staging may be removed only with separate explicit owner approval after the exact-candidate recovery drill. The hardened backup and drill helpers keep plaintext only in process memory/standard input; that drill and the complete client matrix remain first-feed work. Supply-chain checks and the privacy/network boundary are documented.
- Publish 0.1.3 only through `publish_update_feed=false`, then complete the release-blocking clean-account 0.1.3 → 0.1.4 matrix, including exact-production-URL isolated HTTPS, all three framework capabilities, authenticated raw-XML rejection, declared-length and streamed/chunked appcast oversize rejection, proof that larger persistent archives remain eligible, helper loading, exact short/build mismatch rejection, independent archive EdDSA/tamper rejection, atomic replacement, active-work admission, quarantine, Screen Recording authorization and key recovery.
- Activate `publish_update_feed=true` for the first permitted item, 0.1.4 (build 5), only after that complete matrix has recorded evidence. A successful hardened build, direct-download Release or CI run does not complete the updater track.

## Later

- After the hardened ad-hoc update path passes its matrix, separately evaluate Apple Developer Program membership, Developer ID signing and notarization. Preserve the bundle identifier and Sparkle EdDSA trust chain during any migration; membership is not required for the current rollout.
- Consider Universal 2 distribution only after Intel hardware validation and demand review.
- Post-1.0 product ideas: scrolling capture, recording, GIF, delayed capture, OCR and translation.
- Optional paid capabilities may use separately distributed closed-source modules or services behind the existing feature boundary. Ushot code already published under Apache-2.0 remains Apache-2.0 permanently.
